# Автотесты «Калькулятор смет»

Набор автоматизированных проверок для кандидата на позицию QA инженер
(Pryaniky): стенд `https://testquest.pryaniky.com/`, раздел
**Продажи → Калькулятор смет**.

Калькулятор — SPA: стоимость собирается в браузере из `window.PryanikyData`
(`js/data.js`), а итоговая смета генерируется прямо на странице (библиотека
ExcelJS подключается с CDN) и скачивается как `.xlsx`.

Тесты делают то же самое, что делает человек:

1. открывают сайт и переходят в калькулятор;
2. заполняют форму (компания, даты, проект, менеджер, тарифы, число лицензий,
   срок, модули, внедрение, резерв T&M, скидка);
3. жмут «Выгрузить смету в Excel» и скачивают файл;
4. **сверяют** число копеек в Excel (и в итогах на странице) с независимой
   эталонной моделью расчёта (`tests/calc_model.py`), а не доверяют приложению.

Важно: **все ожидаемые значения вычисляются по модели**, а не зашиты
вручную. Модель читает актуальные цены прямо со стенда из `js/data.js`.
Если цены на стенде поменяются — тесты продолжат работать корректно
(в надписях отчёта суммы с «ожидалось» просто пересчитаются).

---

## 1. Требования к окружению

- Python 3.8+ (проверено на 3.10–3.14).
- Доступ в интернет:
  - к стенду TestQuest;
  - к CDN, с которого страница подтягивает ExcelJS (нужно для выгрузки);
  - (однократно) к кэшу браузера Playwright — для установки headless Chromium.
- Операционная система: Windows, Linux или macOS.

Запускающий скрипт сам создаёт виртуальное окружение `.venv` и ставит
зависимости (`playwright`, `openpyxl`), т.е. **работает «из коробки»**.

## 2. Как запустить

### Linux / macOS

```bash
BASE_URL=https://testquest.pryaniky.com ./run-tests.sh
```

### Windows (cmd)

```bat
set BASE_URL=https://testquest.pryaniky.com
run-tests.bat
```

Если переменную `BASE_URL` не задавать — используется стенд
`https://testquest.pryaniky.com` по умолчанию.

Полный прогон занимает **2–3 минуты** (скачивается 4 файла сметы).

### Что вы увидите в конце прогона

Отчёт по каждому кейсу с деталями (`[PASS]`/`[FAIL]`), затем итоговые строки:

```
Блоков: 10, PASS: 9, FAIL/ERROR: 1
RESULT: FAILED        <- автоматический вердикт (см. раздел 5)
EXIT_CODE: 1          <- код возврата скрипта (0 = все кейсы прошли)
```

Код выхода процесса: `0` — все кейсы `PASS`; `1` — есть хотя бы один
`FAIL`/`ERROR`. Это позволяет встраивать прогон в CI/песочницу.

### Результаты из песочницы

- консольный отчёт (в т.ч. `RESULT: PASSED|FAILED`);
- скачанные `.xlsx` сохраняются в папку `artifacts/` рядом с проектом.

## 4. Список тест-кейсов

| Кейс | Что проверяется |
|------|-----------------|
| TC-01 | **Метаданные КП**: имя файла по шаблону «ДД.ММ.ГГГГ, КП по реализации проекта …», лист называется «КП», секция «Облако» |
| TC-02 | **Тариф «Облако»**: цена пакета лицензий совпадает с моделью, НДС «не облагается», зелёное выделение, отсутствие модулей/скидки |
| TC-03 | **Тариф «Коробка»**: секция «Коробка», пакет «лицензия + поддержка», НДС, итог |
| TC-04 | **Лицензии и срок**: поля принимают 50 лиц / 3 мес., коэффициент модулей 1,3, итог за 3 мес. без годового дисконта |
| TC-05 | **Модули**: коэффициент 1,5 (Мессенджер +0,3, Биржа идей +0,2), модуль «в подарок» за 0 ₽, цены модулей |
| TC-06 | **Внедрение**: пресеты, почасовая строка «Настройка портала… 10 чч», НДС по каждой строке, T&M-строка заглушкой |
| TC-07 | **Резерв T&M**: один блок «Резерв на 60 чч», сумма = 60 чч × ставка + НДС |
| TC-08 | **Скидка и «Всего»**: строка «Скидка 10 %» = −10 %, итоги секции совпадают с моделью, в файле нет формул |
| TC-09 | **Минимальная смета**: 1 лицензия на 1 месяц считается корректно |
| TC-10 | **Целостность Excel**: в файле нет «мусора» из шаблона — дублей таблицы «Конфигурация ПО», демо-значений 450 000 ₽, лишних блоков «Резерв», формул |

## 5. Ожидаемый результат и известные дефекты стенда

Текущие «зелёные» кейсы: **TC-01…TC-09**. Кейс **TC-10** намеренно «красный»:
он ищет в выгруженных файлах артефакты шаблона КП и **находит реальные баги
текущей версии стенда**:

1. При выгрузке **только облачного тарифа** в файл попадают продублированные
   строки таблицы «Конфигурация ПО» (модули «Навыки», «Цвет настроения»,
   «Открытки», «Тайный Санта» появляются в файле дважды).
2. При выборе **обоих** тарифов или **только «Коробки»** этот дефект не
   воспроизводится (файл чистый).

Поэтому общий вердикт сейчас — `FAILED` (1 из 10 кейсов падает по причине
бага приложения, что и является результатом тестирования). Если баг на стенде
исправят — TC-10 станет `PASS` и весь прогон даст `PASSED`.

## 6. Как устроена эталонная модель

- `pricedata.load_price_data()` загружает актуальные справочники цен/модулей/
  пресетов внедрения из `https://<стенд>/js/data.js`.
  Если стенд недоступен при парсинге — используются встроенные копии этих
  данных (в пакете они есть), чтобы тесты не падали из-за сети.
- `calc_model.build_section()` полностью повторяет логику `js/calc.js` +
  `js/app.js`: разбивка лицензий по 100 шт., коэффициенты объёма
  (1 / √divisor), годовой дисконт, коэффициент модулей (1 + Σ), рост г/г,
  поддержка для on-prem, НДС 5 %, округление `Math.round`.
- Каждое число в отчёте сверяется с этой моделью, поэтому «ожидалось» в
  логах всегда выводит значение, которое должно быть по логике приложения.

## 7. Ограничения и примечания

- Не запускайте два прогона **параллельно**: они пишут скачанные файлы
  в одну папку `artifacts/`.
- Если выгрузка не происходит (например, CDN с ExcelJS недоступен или
  стенд не отвечает), кейс завершится с ошибкой и в логах будет «подсказка на
  странице» (текст из `#status-hint`) — проверке нечего сверять, когда файл
  не получен.
- В пакете нет исполняемых бинарников (нет `.exe`, `.dll`, `.so`, `.ps1`):
  только исходный код на Python и скрипты обёртки `run-tests.sh`/`run-tests.bat`.
